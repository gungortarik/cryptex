## Security and recovery review

The review traced file selection through the Desktop IPC handler, the signed link, the locked note and device history, transport publication, verified recovery and vault projection. The Desktop request contains a note ID, its expected content hash and selected bytes. The daemon checks the authenticated role, capability and size limit. The signed reference binds the note's hash, Brain and classification. Resolving it requires both the note and link to fall within their authors' effective cutoffs. [IPC handler](../../services/cryptexd/src/ipc/attachment.rs) and [link binding](../../crates/events/src/attachment_link.rs)

A live reader exchange gates transfer. The daemon derives eligible digests and peer slots from verified local history. It checks bounded bytes against the signed SHA-256 before promotion, uses checked regular-file handles, and retains the damaged canonical file in private quarantine. An interrupted replacement can resume from the authenticated peer. Obsidian gets a newly created file whose staged bytes are checked before publication. [Sync reconciliation](../../services/cryptexd/src/managed_profile/sealed_export/attachments.rs), [blob storage](../../services/cryptexd/src/attachment_blobs.rs) and [vault publication](../../crates/projection/src/vault.rs)

## Activation boundary

Ordinary daemon builds reject attachment capture and disable blob exchange. The enrolled Mac and Windows VM previously demonstrated reader compatibility and preserved canonical records through migration. The transport trial uses a fixed pair. Before enabling attachment exchange across roster changes, review retention of offers staged for earlier recipients. Enabling real-profile attachment writes requires a separate owner decision and the complete roster, downgrade and restored-device checks in ADR-0017.
