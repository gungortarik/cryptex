## Finding and correction

On both operating systems, forgetting note A and then explicitly confirming the deletion of unrelated note B produced `CleanupIncomplete(TargetUnavailable)`. The daemon persisted the signed approval but refused to compact a history containing any lifecycle record. The isolated reproducer added only test code to the original candidate. [Failing Windows and macOS tests](https://github.com/gungortarik/cryptex/actions/runs/44675853051)

The corrected compactor accepts authenticated lifecycle records and replays their transitions against the candidate history before replacing the original pack. For notes with a lifecycle dependency, the signed bridge retains the original classification and hash so replay can verify the original author, note identity, class and prior state. The bridge has no note text. Other notes keep their existing visibility. A missing or mismatched class blocks replay. A restore in the purged note's history cannot reintroduce it into the content projection. [Transition checks](../../crates/events/src/security_history.rs) and [compaction](../../services/cryptexd/src/knowledge_materialization/physical_purge.rs)

The regression signs Forget for one note and signs Forget and Restore for a second. It then confirms deletion of an unrelated visible note followed by the restored note, all in the same temporary profile. Reopening and repeating cleanup verifies three lifecycle records, two purge bridges, and the hidden state of the surviving forgotten note. A byte scan checks that the survivor is present and both deleted bodies are absent. Windows CI explicitly checks this test by name and requires all nine Desktop cases to pass. [Native regression](../../services/cryptexd/src/ipc/purge_review/shared_attachment_test.rs)

## Activation boundary

M10 writes are confined to disposable profiles. Physical cleanup covers the eligible signed note, attachment and lifecycle histories exercised here. Other cross-record dependencies can leave cleanup incomplete. These trials do not establish general writing to a compacted production stream or erasure from unreachable devices, external copies or provider-internal history. Real-profile activation requires a separate decision.
