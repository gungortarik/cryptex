## L1 — Sealed whole-object quarantine (ADR-0016 §7.2)

### Source finding (before fix)

`quarantine_sealed_pack` streamed the full `.seg` into quarantine via `quarantine_file_range` (durable: object + metadata sync) but **left the corrupt `.seg` in the canonical device directory**.

Repeated `load_verified_events` / rebuild calls would:
1. Rediscover the same `.seg`
2. Fail closed again
3. Create **additional** quarantine entries for the same bytes

### ADR reading

§7.2 case table: *“Sealed `.seg`: … **Quarantine the whole sealed object** (no in-place edit)”*.  
Parallel `.open` recovery explicitly: quarantine → confirm durable → only then mutate the authoring file. Leaving a discoverable corrupt sealed pack after a durable quarantine copy is **not** whole-object quarantine; “no in-place edit” forbids editing sealed bytes in place, not isolation after durable copy.

### Fix

In `quarantine_sealed_pack`:
1. `quarantine_file_range` (durability confirmed by existing sync sequence)
2. `drop(file)` (Windows unlink requirement)
3. `fs::remove_file(path)` + `sync_parent_directory(path)`

No remove/move before durable quarantine success.

### Tests

- `load_verified_events_fail_closes_and_quarantines_corrupt_sealed_pack` — asserts `.seg` gone, one quarantine entry, second load empty without re-quarantine; integrity error uses `source_relative` not absolute runtime root
- `sealed_pack_corruption_fails_closed_and_quarantines` — asserts `.seg` gone after writer fail-closed path

## L2 — Desktop `cryptexd` dependency vs single-writer

### Evaluation

Desktop `Cargo.toml` depends on the full `cryptexd` path crate. Library call sites in Desktop are only:
- `cryptexd::ipc::desktop_health_ping`
- `cryptexd::ipc::HealthResponse`

Daemon writes go through the **spawned `cryptexd` binary** (sidecar), not in-process `canonical_writer`.

IPC module documents health-only surface (`status.read`); no memory-write IPC.

### Why Cargo features are not a technical guarantee

Workspace feature unification would re-enable `daemon` modules when Desktop and the `cryptexd` binary build together. A `client-ipc` feature alone would be false assurance. A separate client crate would be real isolation but is **out of M2 scope**.

### Master Spec boundary (preserved)

- `cryptexd` process is the only supported canonical writer
- Desktop does not call `append_memory_note` / `canonical_writer` (grep-verified)
- IPC exposes no canonical write API

**M2 gate:** NON-BLOCKER. Residual defense-in-depth: future in-process Desktop writer calls would violate Master Spec — track as post-M2 client-crate split, not silent deferral of an active violation.

## F4 — Path leakage on error/log surfaces

### Fixed now

Sealed-pack integrity messages in rebuild + `load_verified_events` use pack-relative `canonical/events/<stem>/<index>.seg` instead of `path.display()`.

### Residual (NON-BLOCKER for M2)

`EventSigningKeyError::AlreadyExists`, identity/install `AlreadyExists`, and some `Path(os_error)` strings may still embed absolute runtime paths under the app-data root. These are typed operational errors, not memory-body logs. Broad redaction of all OS path errors is a larger hygiene pass outside this sealed-quarantine closeout slice.

Evidence that sealed integrity path no longer embeds runtime root: regression asserts in `load_verified_events_fail_closes_and_quarantines_corrupt_sealed_pack`.

## F5 — Quarantine containment

All quarantine writes go through `attribution_parent` → `quarantine_events_root(app_data_root)/<attribution>/…` and `q_*` helpers using `quarantine_fs_path`, which rejects `.` / `..` components. `validate_source_relative` rejects absolute/`..` metadata. No quarantine API accepts an arbitrary destination root.

**M2 gate:** NON-BLOCKER. Optional extra canonicalize-and-strip-prefix assert remains optional hardening, not an ADR gap for M2.

## F6 — Staging cleanup and `\\?\` scope

### Staging (FIXED)

`quarantine_file_range` now holds a `StagingCleanup` guard that removes `.staging-*` on any failure before successful `place_staging_as_object`; disarmed after placement. Rename-failure paths already removed staging.

Regression: `staging_removed_when_source_range_read_fails`.

### Extended path beyond quarantine (NON-BLOCKER)

ADR Windows addendum §4 non-goals: *“Applying extended paths to non-quarantine writers (canonical `.open`/`.seg` layout) in this addendum”*. Canonical writers intentionally remain non-prefixed; quarantine-only `\\?\` matches accepted addendum.
